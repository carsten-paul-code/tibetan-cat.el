#+TITLE: Zettel in Translation Workflow — Feature Design
#+DATE: 2026-04-24
#+AUTHOR: Carsten Paul + Claude
#+STATUS: v1 approved — Phase 1 shipped, Phase 2 next

* Intent

Integrate the main zettelkasten (=~/buddhist-studies/knowledge/zettelkasten/=,
~1010 Denote-managed org files today) into the CAT translation workflow
as *the authoritative source* for:

1. *User-preferred translations* (per term, per language), overriding
   dictionary glosses but deferring to Resources/Custom.
2. *Cross-document consistency* — the same term resolves to the same
   preferred gloss everywhere in every analysis file.
3. *A Claude response cache* — explanations Claude gave for a term
   on one segment are written to the zettel and re-used instead of
   re-requested on subsequent segments / documents.
4. *84000 encyclopaedic text* — for tokens tagged ~<term>~ by
   84000Definitions, the zettel caches the paragraph so U3's
   =*** Buddhist Terms= subsection reads from the zettel instead of
   re-scraping dict sources every render.

Result: the zettelkasten becomes a *personal lexicon* that grows
automatically as Carsten translates, AND each entry accumulates
structured, reusable knowledge (Claude's reading, 84000's definition,
user's own notes, backlinks to every segment that referenced it).

* Why this feature *after* the reorg

The 2026-04-24 buddhist-studies reorg moved the zettelkasten from
the top-level =~/buddhist-studies/zettelkasten/= to
=~/buddhist-studies/knowledge/zettelkasten/=.  Without that move:

- =org-agenda-files= scanned 1800+ files every startup, hanging Emacs
  (the immediate pain that triggered the reorg).
- The zettelkasten's role was ambiguous — zettels, concepts, and
  per-course notes mingled at the root.

Post-reorg, =knowledge/zettelkasten/= is a clean canonical home for
the feature's writes, and the CAT tool's existing
=tibetan-thesaurus-kramer-source-directory= already points at it.

* User-visible behaviour

** In the Interlinear Gloss

Current (before feature):

#+begin_example
  [[term-bdag][bdag]] [I, self]
#+end_example

With feature, when a zettel exists for ~bdag~:

#+begin_example
  [[id:20260224T120000][bdag]] ♦ [ich / selbst]
#+end_example

Changes:

- The link target is now the zettel's ~:ID:~, not a local
  =term-bdag= radio-target.  Click jumps to the zettel file.
- ♦ marker (distinct from the existing ★ used for
  Resources/Custom) indicates "this token has a zettel".
- The gloss text shown is ~:preferred-de:~ (target language is
  ~de~) and falls back to ~:preferred-en:~ if German is empty.
  The bilingual DE // EN pair still lives in the Detailed
  Dictionary entry below for reference.

** In the Detailed Dictionary

Zettel entries get a new source block at rank 2 (after Resources,
before Steinert):

#+begin_example
  ◆ བདག [bdag] ([[id:20260224T120000][Zettel ↗]])
    [Zettel: preferred]
      ich / selbst
    [Zettel: notes excerpt]
      <first-paragraph teaser of user's ** Notes>
    [Resources (provided)]
      ich, selbst // I, self
    [Steinert/01-Hopkins2015]
      I (first person pronoun); oneself
    ...
#+end_example

** In the Grammar section's Buddhist Terms subsection

Current U3 behaviour reads 84000Definitions fresh every render.
With the feature, when a zettel exists for the term:

#+begin_example
  *** Buddhist Terms
  - ཚད་མེད་བཞི་པོ [tshad med bzhi po] ♦ [[id:ZETTEL-ID][Zettel ↗]]
    four immeasurables (Skt: caturapramāṇa): the meditations on love,
    compassion, joy, equanimity; also called the four abodes of Brahmā …
    — [84000 Definitions via zettel cache]
#+end_example

If no zettel exists AND the token is ~<term>~-tagged by 84000:
*auto-create* a zettel scaffold (see § 6 below), seed its
~** 84000 Definitions= section with the current 84000 body, and
link back from the segment.

* Zettel schema

** New properties (PROPERTIES drawer)

| Property           | Meaning                                  | Example                |
|--------------------+------------------------------------------+------------------------|
| ~:ID:~             | Org-id, unchanged from Denote default    | 20260224T120000        |
| ~:wylie:~          | Canonical Wylie (lowercase, trimmed)     | tshad med bzhi po      |
| ~:script:~         | Tibetan script                           | ཚད་མེད་བཞི་པོ          |
| ~:sanskrit:~       | Skt (when lexically one-to-one)          | caturapramāṇa          |
| ~:preferred-de:~   | Target-lang gloss (German)               | die vier Unermesslichen |
| ~:preferred-en:~   | Target-lang gloss (English)              | four immeasurables     |
| ~:claude-cached:~  | Timestamp of the cached Claude body      | 2026-04-24             |
| ~:steinert-84000:~ | "yes" when 84000 tag is present          | yes                    |

** Backwards compatibility with Pass-5b Thesaurus zettels

Existing Pass-5b thesaurus zettels use ~:primary:~ for the bilingual
DE // EN string and have no separate ~:preferred-de:~ /
~:preferred-en:~ fields.

Migration strategy: READER accepts both formats; writer-on-create
emits the new format; manual migration command
(=M-x tibetan-thesaurus-migrate-to-v2=) splits ~:primary:~ strings
into the new pair.  Timing: the migration command runs
lazy / on-demand — no big-bang rewrite of 1010 files on upgrade.

* Architecture — data flow

** Zettel index

A fast lookup table built on first access, cached by mtime of the
zettelkasten directory:

#+begin_src elisp
  tibetan-zettel-index  →  hash :test 'equal
    KEY   = downcased Wylie string
    VALUE = plist (:id :path :wylie :script :preferred-de :preferred-en
                   :sanskrit :steinert-84000 :claude-cached-p)
#+end_src

Rebuild triggers:
- First lookup after Emacs start.
- Any write via the feature's creation / edit commands.
- Explicit =M-x tibetan-zettel-reload=.

** Detection pass

In =tibetan-analysis-generate-content='s enriched-vocab-pairs
builder, right after ~word-clean~ is computed:

1. Convert to Wylie (existing helper ~--token-wylie~).
2. Look up in =tibetan-zettel-index=.
3. If hit: store the zettel plist in a per-token metadata table.

** Gloss ranking

Add a new source to =tibetan-vocab-multisource-entries= at rank 2
(after Resources at rank 1 — per Carsten's spec "level 2, after
provided vocabulary"):

#+begin_src
  Rank 1: Resources (per-document vocabulary.org)
  Rank 2: Zettel-preferred (NEW — this feature)
  Rank 3: Custom
  Rank 4: Thesaurus (Pass 5b, Kramer-seeded — to be unified with Rank 2)
  Rank 5: Corpus-specific Steinert sub-dict
  Rank 6: Steinert general
  …
#+end_src

Unification: in Phase 1, Rank 2 reads Zettel AND Rank 4 still reads
legacy Pass-5b Thesaurus files.  After migration command runs
(Phase 6), Rank 4 drops away — a single rank covers all user
zettels.

** Marking in Interlinear

Extend =tibetan-interlinear--format-gloss-entry= to accept a
~:zettel-id~ arg.  When present:

- Emit ~[[id:ZETTEL-ID][wylie]]~ instead of ~[[term-xxx][wylie]]~.
- Insert ♦ between the link and the gloss bracket (mirrors ★ for
  Resources).
- New face ~tibetan-analysis-zettel-face~ applied via font-lock to
  ♦ and optionally to the gloss text.

** Detailed Dictionary head line

Zettel hit prepends a new ink-spot to the DD head line before the
Steinert URL:

#+begin_example
  ◆ ཚད་མེད་བཞི་པོ [tshad med bzhi po] ♦ [[id:ZETTEL-ID][Zettel ↗]] · [[https://dict.steinert...][Steinert ↗]]
#+end_example

* Auto-creation

** Trigger

During enriched-vocab-pairs building, when:

1. The token has an 84000Dict / 84000Definitions entry tagged
   ~<term>~ (the U3 detector).
2. NO zettel currently exists (lookup miss).

** What gets created

Filename follows Denote convention:

#+begin_example
  <TIMESTAMP>--<wylie-slug>__glossar__buddhist-term.org
#+end_example

Example:

#+begin_example
  20260424T143022--tshad-med-bzhi-po__glossar__buddhist-term.org
#+end_example

Content:

#+begin_src org
  #+TITLE: tshad med bzhi po — four immeasurables
  :PROPERTIES:
  :ID:       20260424T143022
  :wylie:    tshad med bzhi po
  :script:   ཚད་མེད་བཞི་པོ
  :sanskrit: caturapramāṇa
  :preferred-de: [to be researched]
  :preferred-en: four immeasurables
  :steinert-84000: yes
  :END:

  * Notes

  * 84000 Definitions
  :PROPERTIES:
  :TERM_CACHE: t
  :END:

  <term> four immeasurables (Skt: caturapramāṇa): the meditations on love
  (maitrī), compassion (karuṇā), joy (muditā), and equanimity (upekṣā), as
  well as the states of mind and qualities of being that result from their
  cultivation.  They are also called the four abodes of Brahmā
  (caturbrahmavihāra).  … [full 84000Definitions body]

  (Original glossary entry: https://84000.co/glossary/entity-41080.html)

  * Claude Explanation
  :PROPERTIES:
  :TERM_CACHE: t
  :END:

  [awaiting first analysis]

  * Back-links
  :PROPERTIES:
  :TERM_CACHE: t
  :END:
  - [[id:SEG-016-GAL-CHEN-ID][gal-chen-nyi-shu seg-16]]
#+end_src

** User control

Auto-creation is opt-in via a defcustom:

#+begin_src elisp
  (defcustom tibetan-zettel-auto-create-on-buddhist-term 'ask
    "Behaviour when a <term>-tagged token has no zettel yet.
  `always' — create silently.
  `ask'    — prompt with y-or-n-p, naming the term.
  nil      — never create, surface term in Buddhist Terms block only.")
#+end_src

Default ~'ask~ so Carsten sees every auto-creation opportunity and
can decline terms that are too generic (like ~chos~ or ~sems~).

* Claude-cache

** Write path

When a Claude response arrives (existing
=tibetan-analysis--insert-claude-sections= path):

1. Iterate the Claude Vocabulary lines (parsed per Pass 5c).
2. For each line, look up the token's zettel.
3. If zettel exists AND its ~* Claude Explanation~ section is empty
   (contains only ~[awaiting first analysis]~ or is blank):
   - Write the Claude Vocabulary line's gloss-field body to that
     section.
   - Update ~:claude-cached:~ property to today.

** Read path

U3's Buddhist Terms renderer:

1. Look up each detected Buddhist term in zettel index.
2. If zettel exists AND ~:claude-cached:~ is set AND the ~* Claude
   Explanation~ section has content:
   - Use the zettel's Claude explanation.
   - Mark with ~[via zettel cache]~ suffix so it's clear no fresh
     Claude call was made.
3. Else: fall back to 84000Definitions body (current U3 behaviour).

** Invalidation

Explicit only — no automatic TTL.  User commands:

- =M-x tibetan-zettel-invalidate-claude-cache= on a zettel: clears
  ~:claude-cached:~ and the Claude Explanation body.  Next analysis
  referencing the term will refill from a fresh Claude call.

Rationale: Claude's explanations of stable Buddhist terminology
shouldn't drift over time.  When they do (better Claude model,
corrected user prompt), the user explicitly bumps the cache.

** Cross-document consistency

The same Claude explanation in every segment that references the
term.  A user edit to the zettel's Claude-Explanation body
propagates to every analysis on next regen.

* Back-link maintenance

Every analysis appends ~[[id:SEG-ID][short-label]]~ to the zettel's
~* Back-links~ section, deduped.  A zettel thus accumulates every
context it's been referenced in — a lightweight reverse-index.

Dedup key: the seg file's ~:ID:~ property (see the existing
~tibetan-thesaurus-segments-affected-by-zettel~ for precedent).

Garbage collection: when a seg file is deleted or its term list no
longer includes the zettel, the back-link stays (we don't know if
it's deliberate historical context).  A separate command =M-x
tibetan-zettel-gc-backlinks= scans all referenced segs and removes
stale links on demand.

* Design decisions (approved 2026-04-24)

All six open questions resolved in favour of the recommended
options.  Recorded here so Phase 1 implementation starts from a
fixed spec.

1. *Zettel identification.*  *Decided: Denote file-tag ~__glossar~
   OR presence of ~:wylie:~ property (OR semantics).*  The index
   builder treats either signal as sufficient; auto-created entries
   always carry both (tag via Denote filename, property via
   :wylie:).  Manual zettels with just the tag get picked up too.
   Rejected: a dedicated ~:TIBETAN_TERM: t~ property — would have
   been a third marker that duplicates the tag.

2. *New-zettel location.*  *Decided: flat in
   =knowledge/zettelkasten/=* with the Denote tag chain
   ~__glossar__buddhist-term~ (or similar) distinguishing
   auto-creates from hand-written zettels.  Matches Denote's
   assumption that a zettelkasten is a flat tag-indexed namespace;
   tag-based filters are cheap once the index is built.  Rejected:
   nested =tibetan-terms/= subdirectory.

3. *Pass-5b Thesaurus zettels.*  *Decided: migrate into the main
   zettelkasten.*  Phase 6 ships the migration command
   =M-x tibetan-thesaurus-migrate-to-knowledge-zettelkasten= which
   moves every Kramer-format file from =~/Documents/tibetan-
   thesaurus/= into =~/buddhist-studies/knowledge/zettelkasten/=
   and rewrites the ~:primary: DE // EN~ string into paired
   ~:preferred-de:~ / ~:preferred-en:~ properties.  Single source
   of truth after migration; no more dual-directory divergence
   risk.  Phase 1's reader accepts both schemas during the
   transition.

4. *Auto-creation default.*  *Decided: ~'ask~.*  Each auto-create
   opportunity pops a y-or-n-p naming the term and its 84000
   gloss — you accept or reject per-term for the first stretch of
   use.  Switch to ~'always~ later via defcustom once the
   <term>-tag heuristic has proven itself on your corpus (i.e.
   you've seen enough ~'ask~ prompts to trust them).

5. *Claude-cache stamping.*  *Decided: yes, with prompt-version +
   model stamped on each cache entry.*  Properties on zettels with
   a populated ~* Claude Explanation~ section:

   - ~:claude-cached: YYYY-MM-DD~ — creation timestamp.
   - ~:claude-model: claude-opus-4.7~ (or whatever was used).
   - ~:prompt-version: <hash of tibetan-analysis--claude-system-prompt>~.

   On read, Phase 5 compares the current prompt hash against the
   cached one.  Mismatch → treat the cache as stale, fire a fresh
   Claude call, overwrite the cache with the new response, update
   all three stamps.  Means that when the system prompt is tightened
   (as it was in commit a1de885 for U1+U2), every cached entry gets
   invalidated and refreshed on next reference, not manually.

6. *German =:preferred-de:= auto-fill policy.*  *Decided: stay
   empty until you fill it manually.*  Auto-created zettels
   initialize ~:preferred-de:~ with the literal string
   ~[to be researched]~; the translation-gaps report (~C-c u z g~)
   surfaces these as work items.  Claude responses do NOT
   auto-populate the field — the German gloss remains your
   curation, ensuring the translation-gap workflow stays
   meaningful and that every German rendering across the corpus
   reflects a deliberate choice.  The English ~:preferred-en:~
   IS auto-populated from 84000's gloss when available (since the
   English is canonical reference material, not personal
   interpretation).

* Success criteria

The feature is done when:

1. Every translation-relevant zettel in =knowledge/zettelkasten/=
   surfaces as ♦-marked, linked, preferred-gloss in every analysis
   that references its term.
2. Opening seg-NNN.org for a new text in
   =Gotrapaṭala.org= or similar shows zero /novel/ Claude calls for
   Buddhist terms already explained in the zettelkasten (100% cache
   hit on repeated-across-documents terms).
3. The zettelkasten grows organically: after a semester of
   translation work, ~50 auto-created Buddhist-term zettels exist
   that didn't before, each with their 84000 Definitions, Claude
   Explanation, back-links to the segments that prompted them, and
   a user-curated Notes section.
4. =M-x tibetan-zettel-reload= + a full folder =C-c u r= batch
   reanalyze is idempotent — no drift between runs.
5. Full test suite passes (≥ 1500 tests after Phase 7).

* Non-goals

- *Replacing Denote.*  The zettelkasten stays Denote-managed.  This
  feature adds translation-specific reads / writes; Denote's capture,
  naming, and search remain as-is.
- *Replacing org-roam.*  Org-roam's DB queries are orthogonal; this
  feature writes plain org property drawers readable without the DB.
- *Cross-zettel graph features* (like "show all zettels tagged
  ~dzogchen~").  Those exist via org-roam / Denote already.
